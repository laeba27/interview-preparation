1. How to Approach a Problem

In plain words

DSA means Data Structures (ways to store data) and Algorithms (step-by-step recipes to solve a problem). In an interview, they want to see how you think, not only the final code.

Think of cooking a new dish. First you read the recipe and check what is in the fridge. Then you cook a simple version. Only after that do you make it faster or tastier.

Key points

  • Understand the question first. Say it again in your own words.
  • Ask questions: Can the array be empty? Can numbers be negative? Are there duplicates?
  • Try a tiny example by hand, like [2, 7, 11]. Write the answer you expect.
  • Start with the simple (brute force) idea. Brute force means "try every possibility". It is slow, but correct.
  • Then improve it. Ask: "What work am I repeating? Can a HashMap or sorting help?"
  • Test your code with your tiny example and with edge cases (empty input, one item).

static int[] twoSumBrute(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) {          // first number
        for (int j = i + 1; j < nums.length; j++) {  // second number, after the first
            if (nums[i] + nums[j] == target) {        // do they add up?
                return new int[] { i, j };            // yes: return both positions
            }
        }
    }
    return new int[] { -1, -1 };                      // no pair found
}

Time & space: O(n²) time — every pair is checked. O(1) extra space. (The faster HashMap version is in topic 7.)

Remember: understand → example → brute force → improve → test. Talk out loud at every step.
Practice: Two Sum (#1), Contains Duplicate (#217).

2. Big-O & Complexity

In plain words

Big-O tells you how the work grows when the input grows. We write n for the input size (for example, how many items are in an array). Time complexity = how many steps. Space complexity = how much extra memory.

Finding a friend's name in your phone contacts. Scrolling one by one gets slower when you have more contacts (O(n)). Typing the name in search is almost instant, even with 5,000 contacts (close to O(1) or O(log n)).

Key points

  • O(1) = constant. Same time for any size. Example: arr[5].
  • O(log n) = we cut the problem in half each step. Example: binary search.
  • O(n) = we look at each item once. Example: one loop.
  • O(n log n) = good sorting. O(n²) = a loop inside a loop.
  • Drop constants: O(2n) is just O(n). Keep the biggest part: O(n² + n) is O(n²).
  • Rough rule: a computer does about 100 million simple steps per second.

static void examples(int[] arr) {
    int first = arr[0];                       // O(1): one step, any size

    int sum = 0;
    for (int x : arr) {                       // O(n): one pass over the array
        sum += x;
    }

    int pairs = 0;
    for (int i = 0; i < arr.length; i++) {     // O(n²): loop inside a loop
        for (int j = 0; j < arr.length; j++) {
            pairs++;
        }
    }
    System.out.println(first + " " + sum + " " + pairs);
}

Time & space: count the loops. One loop over n = O(n). A loop inside a loop = O(n²). Halving each time = O(log n).

Remember: Big-O is about growth. If n can be 100,000, an O(n²) answer is usually too slow — look for O(n) or O(n log n).
Practice: think about the Big-O of every problem you solve from now on.

3. Recursion & the Call Stack

In plain words

Recursion is when a function calls itself with a smaller problem. It needs a base case: a small case where it stops and answers directly. The call stack is where Java remembers every function that is still waiting for an answer.

Russian dolls. You open a doll and find a smaller doll inside. You keep opening until you reach the tiny doll that does not open. That tiny doll is the base case.

Key points

  • Every recursive function needs: a base case (stop) and a recursive case (call itself on a smaller input).
  • Forget the base case → the function never stops → StackOverflowError.
  • Each waiting call uses memory on the stack. So recursion depth n = O(n) space.
  • Trust the function: assume fact(n - 1) already works, and just use its answer.
  • Recursion is the base of trees, backtracking, and divide & conquer.

static int fact(int n) {
    if (n <= 1) {              // base case: stop here
        return 1;
    }
    return n * fact(n - 1);    // recursive case: smaller problem
}

Time & space: O(n) time — n calls. O(n) space — n calls wait on the stack at the same time.

Remember: base case first, then a smaller call. Draw the call stack when you feel lost.

4. Java Toolkit for DSA

In plain words

Java already gives you ready-made data structures in java.util. You do not need to build them yourself. You just need to know which one to pick.

A toolbox. A hammer for nails, a screwdriver for screws. ArrayList for a growing list, HashMap for fast lookup, ArrayDeque for a stack or a queue.

Key points

  • int[] = fixed size array. ArrayList = array that can grow.
  • HashMap = key → value pairs. HashSet = unique items. Both find things in O(1) on average.
  • ArrayDeque = use it as a stack or a queue. (Avoid the old Stack class.)
  • PriorityQueue = always gives you the smallest item first (a heap).
  • Arrays.sort(arr) sorts an array. Collections.sort(list) sorts a list.
  • Collections hold objects, so write Integer, not int: List<Integer>.

5. Bit Manipulation

In plain words

Computers store numbers in binary: only 0s and 1s. Each 0 or 1 is called a bit. Example: 5 = 101, 3 = 011. Bit tricks work on these 0s and 1s directly. They are very fast.

A row of light switches. Each switch is on (1) or off (0). Bit operations flip, check, or compare the switches.

Key points

  • AND a & b: 1 only if both bits are 1.
  • OR a | b: 1 if at least one bit is 1.
  • XOR a ^ b: 1 if the bits are different. Important: x ^ x = 0 and x ^ 0 = x.
  • Shift: x << 1 doubles x. x >> 1 halves x.
  • (n & 1) == 1 means n is odd. n & (n - 1) removes the lowest 1 bit.

// Single Number: every number appears twice except one.
// Pairs cancel out with XOR (x ^ x = 0), so only the single one is left.
static int singleNumber(int[] nums) {
    int result = 0;
    for (int x : nums) {
        result = result ^ x;      // XOR everything together
    }
    return result;
}

// Count how many bits are 1
static int countOnes(int n) {
    int count = 0;
    while (n != 0) {
        n = n & (n - 1);          // remove the lowest 1 bit
        count++;
    }
    return count;
}

Time & space: singleNumber is O(n) time, O(1) space — one pass, one variable.

Remember: XOR cancels pairs. n & 1 checks odd/even. This topic is less common — learn the basics and move on.

6. Arrays & Strings

In plain words

An array is a row of boxes, side by side in memory. Each box has a number called an index. The first index is 0, not 1. A string is like an array of characters.

A row of lockers in a school. Each locker has a number. If you know the number, you walk straight to it. You don't open all the other lockers.

Key points

  • Reading or changing arr[i] is O(1) — instant.
  • Inserting or deleting in the middle is O(n) — all later items must move over.
  • An int[] has a fixed size. Use ArrayList if it must grow.
  • Java strings can't be changed (they are immutable). To build a string piece by piece, use StringBuilder.
  • Useful: s.length(), s.charAt(i), s.toCharArray().

static int findMax(int[] arr) {
    int max = arr[0];                         // start with the first item
    for (int i = 1; i < arr.length; i++) {    // look at every other item
        if (arr[i] > max) {                   // found a bigger one?
            max = arr[i];                     // remember it
        }
    }
    return max;

static String reverse(String s) {
    StringBuilder sb = new StringBuilder();   // fast way to build a string
    for (int i = s.length() - 1; i >= 0; i--) {  // walk from the end
        sb.append(s.charAt(i));
    }
    return sb.toString();                     // "abc" -> "cba"
}

Time & space: findMax is O(n) — we look at each item once. O(1) extra space.

Remember: index starts at 0, ends at length - 1. Use StringBuilder to build strings in a loop.

7. Hashing

In plain words

Hashing turns a key (like a name) into a box number. So you can store and find things almost instantly. In Java you use HashMap (key → value) and HashSet (only keys).

A coat check at a theatre. You give your coat and get ticket 42. Later you show ticket 42, and they go straight to hook 42. Nobody searches through every coat.

Key points

  • Add, find and remove are O(1) on average.
  • Use a HashSet for "have I seen this before?"
  • Use a HashMap for counting: "how many times does each word appear?"
  • Use a HashMap to remember positions: "where did I see this number?"
  • Hashing trades memory for speed: O(n) extra space to save time.
  • A HashMap has no order. Use TreeMap if you need sorted keys (topic 14).

static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // number -> its index
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];                   // the partner we want
        if (seen.containsKey(need)) {                  // seen the partner before?
            return new int[] { seen.get(need), i };    // yes: done
        }
        seen.put(nums[i], i);                          // no: remember this number
    }
    return new int[] { -1, -1 };                       // no answer
}

// Count how often each character appears
static Map<Character, Integer> countChars(String s) {
    Map<Character, Integer> count = new HashMap<>();
    for (char c : s.toCharArray()) {
        count.put(c, count.getOrDefault(c, 0) + 1);   // old count + 1
    }
    return count;
}

Time & space: O(n) time — one pass, each lookup is O(1). O(n) space for the map.

Remember: when you see "find a pair", "count", or "seen before", think HashMap or HashSet.
Practice: Two Sum (#1), Valid Anagram (#242), Group Anagrams (#49).

8. Linked Lists

In plain words

A linked list is a chain of nodes. Each node holds a value and a pointer (arrow) to the next node. The first node is the head. The last node points to null (nothing).

A treasure hunt. Each clue tells you where the next clue is. To reach clue 5, you must follow clues 1, 2, 3 and 4 first.

Key points

  • No index. To find the 5th item, walk from the head. That is O(n).
  • Adding or removing at the head is O(1) — just change one arrow.
  • Always check for null before you use node.next.
  • A dummy node (a fake first node) makes many problems easier. You return dummy.next.
  • Doubly linked list: each node also points back to the previous node.

9. Stacks

In plain words

A stack is a pile. You add to the top (push) and remove from the top (pop). The last thing in is the first thing out. This is called LIFO (Last In, First Out).

A stack of plates. You put a clean plate on top. You also take a plate from the top. You never pull one from the bottom.

Key points

  • push(x) adds on top. pop() removes the top. peek() looks at the top without removing it.
  • All three are O(1).
  • In Java use Deque<Integer> stack = new ArrayDeque<>();
  • Use a stack for matching brackets, "undo" features, and going back to the most recent thing.
  • Recursion uses a stack inside (the call stack, topic 3).

static boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') {
            stack.push(c);                        // opening: save it
        } else {
            if (stack.isEmpty()) return false;    // closing with nothing open
            char top = stack.pop();               // the latest opening bracket
            if (c == ')' && top != '(') return false;
            if (c == ']' && top != '[') return false;
            if (c == '}' && top != '{') return false;
        }
    }
    return stack.isEmpty();                       // nothing left open = valid
}

Time & space: O(n) time — each character is pushed and popped at most once. O(n) space for the stack.

Remember: stack = plates = last in, first out. Think "stack" when the newest item must be handled first.
Practice: Valid Parentheses (#20), Min Stack (#155), Baseball Game (#682).

10. Queues & Deques

In plain words

A queue is a line. You join at the back (offer) and leave from the front (poll). The first in is the first out: FIFO. A deque ("deck") is a line where you can add or remove at both ends.

The queue at a ticket counter. The person who came first gets served first. New people join at the back.

Key points

  • offer(x) adds at the back. poll() removes from the front. peek() looks at the front.
  • All are O(1) with ArrayDeque.
  • poll() returns null when the queue is empty — check isEmpty() first.
  • Queues are the heart of BFS (breadth-first search, topics 16 and 38): visit things level by level.
  • A deque has offerFirst, offerLast, pollFirst, pollLast.

// Number of Recent Calls: count calls in the last 3000 ms
class RecentCounter {
    Queue<Integer> times = new ArrayDeque<>();   // call times, oldest at the front

    int ping(int t) {
        times.offer(t);                              // new call joins at the back
        while (times.peek() < t - 3000) {            // oldest call is too old?
            times.poll();                            // remove it from the front
        }
        return times.size();                         // calls left are all recent
    }
}

Time & space: each time is added once and removed once, so O(1) on average per call. O(n) space for the queue.

Remember: queue = ticket line = first in, first out. Stack for "newest first", queue for "oldest first".

11. Heaps & Priority Queues

In plain words

A heap always keeps the smallest (or largest) item ready at the top. A min-heap gives the smallest first. A max-heap gives the largest first. In Java it is called PriorityQueue.

A hospital emergency room. Patients are not seen in arrival order. The most serious patient always goes first.

Key points

  • peek() (see the top) is O(1). offer and poll are O(log n).
  • Java's PriorityQueue is a min-heap by default.
  • Max-heap: new PriorityQueue<>(Collections.reverseOrder()).
  • Great for "the k largest", "the k smallest", "the next most important".
  • Trick: to find the k largest, keep a min-heap of size k. The top is the k-th largest.

static int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();  // min-heap
    for (int x : nums) {
        heap.offer(x);                // add the number
        if (heap.size() > k) {        // too many?
            heap.poll();              // remove the smallest
        }
    }
    return heap.peek();               // smallest of the k largest
}

Time & space: O(n log k) time — n numbers, each heap step costs log k. O(k) space.

Remember: "k largest" → min-heap of size k. "k smallest" → max-heap of size k.

12. Binary Trees

In plain words

A tree is made of nodes connected like branches. The top node is the root. In a binary tree, each node has at most two children: left and right. A node with no children is a leaf.

A family tree, upside down. The grandparent is at the top (root). Each person has up to two children below them.

Key points

  • Each node has a value, a left child and a right child (either can be null).
  • Height / depth = the number of levels from the root to the deepest leaf.
  • Most tree problems use recursion: solve for the left side, solve for the right side, combine.
  • The base case is almost always if (root == null).
  • DFS (depth-first) uses recursion. BFS (breadth-first) uses a queue. More in topic 38.

class TreeNode {
    int val;
    TreeNode left, right;          // children (can be null)

static int maxDepth(TreeNode root) {
    if (root == null) return 0;            // empty tree has depth 0
    int left = maxDepth(root.left);        // depth of the left side
    int right = maxDepth(root.right);      // depth of the right side
    return 1 + Math.max(left, right);      // this node + the deeper side
}

static void preorder(TreeNode root, List<Integer> out) {
    if (root == null) return;
    out.add(root.val);                     // 1. visit the node
    preorder(root.left, out);              // 2. then the left side
    preorder(root.right, out);             // 3. then the right side
}

Time & space: O(n) time — each node is visited once. O(h) space for the call stack, where h is the tree height.

Remember: base case root == null, then trust the recursion on left and right.

13. Binary Search Trees

In plain words

A BST (Binary Search Tree) is a binary tree with one rule: everything on the left is smaller than the node, and everything on the right is bigger. This rule makes searching fast.

A "guess the number" game. "Is it 8?" — "Smaller." Now you ignore everything above 8. Each answer throws away half the choices.

Key points

  • Search, insert and delete take O(h) steps, where h is the height.
  • If the tree is balanced (bushy), h is about log n, so it is fast.
  • If you insert sorted numbers (1, 2, 3, 4…), the tree becomes a long line. Then h = n and it is slow.
  • Inorder traversal (left, root, right) of a BST gives the values in sorted order.
  • Validate a BST by checking each node is inside a (min, max) range, not just against its parent.

static TreeNode search(TreeNode root, int target) {
    TreeNode cur = root;
    while (cur != null) {
        if (target == cur.val) return cur;     // found it
        if (target < cur.val) cur = cur.left;  // smaller: go left
        else cur = cur.right;                  // bigger: go right
    }
    return null;                               // not in the tree
}

static TreeNode insert(TreeNode root, int value) {
    if (root == null) return new TreeNode(value);   // empty spot: put it here
    if (value < root.val) root.left = insert(root.left, value);
    else root.right = insert(root.right, value);
    return root;
}

Time & space: O(h) time — one path from root down. O(log n) if balanced, O(n) in the worst case.

Remember: smaller → left, bigger → right. Inorder of a BST is sorted.

14. Balanced Trees & TreeMap

In plain words

A balanced tree fixes itself after every insert, so it never becomes a long line. Its height stays about log n. Java's TreeMap and TreeSet are balanced trees (red-black trees) that are ready to use. Advanced — come back later for how the balancing works. For now, just learn to use TreeMap.

A dictionary. Words are always kept in order. You can quickly find a word, or "the word just before" or "the word just after" it.

Key points

  • You almost never write AVL or red-black trees in interviews. You use TreeMap / TreeSet.
  • Like HashMap, but the keys are kept sorted. Each operation is O(log n).
  • floorKey(x) = biggest key ≤ x. ceilingKey(x) = smallest key ≥ x.
  • firstKey() = smallest key. lastKey() = biggest key.
  • Use it when you need "the closest value" or sorted order while adding items.

15. Tries

In plain words

A trie (say "try") is a tree for words. Each step down the tree is one letter. Words that start the same way share the same path. It is great for prefix searches (a prefix is the start of a word, like "ca" in "cat").

The search box on your phone. You type "ca" and it suggests "cat", "car", "call". All of them share the start "c" → "a".

Key points

  • Each node has up to 26 children (one per letter a–z) and a flag isEnd ("a word ends here").
  • Insert and search take O(L), where L is the length of the word. The number of words does not matter.
  • startsWith(prefix) is very fast — that is the main reason to use a trie.
  • Used for autocomplete, spell check and word games.

class Trie {
    Trie[] children = new Trie[26];   // one slot per letter a-z
    boolean isEnd = false;            // does a word end here?

    void insert(String word) {
        Trie node = this;
        for (char c : word.toCharArray()) {
            int i = c - 'a';                       // 'a' -> 0, 'b' -> 1 ...
            if (node.children[i] == null) {
                node.children[i] = new Trie();     // make the path if missing
            }
            node = node.children[i];               // step down
        }
        node.isEnd = true;                         // mark the end of the word
    }

    boolean search(String word) {
        Trie node = walk(word);
        return node != null && node.isEnd;         // path exists AND a word ends here
    }

    boolean startsWith(String prefix) {
        return walk(prefix) != null;               // path exists
    }

    Trie walk(String s) {                          // follow letters, null if missing
        Trie node = this;
        for (char c : s.toCharArray()) {
            node = node.children[c - 'a'];
            if (node == null) return null;
        }
        return node;
    }
}

Time & space: O(L) per operation — one step per letter. Space grows with the total letters stored.

Remember: "prefix" or "starts with" in the question → think trie.

16. Graphs & Traversal

In plain words

A graph is a set of nodes (also called vertices) joined by edges (lines). Unlike a tree, a graph can have loops (cycles) and no root. We usually store it as an adjacency list: for each node, a list of its neighbours.

A map of cities and roads. Cities are nodes. Roads are edges. "Can I drive from city A to city B?" is a graph question.

Key points

  • Undirected edge = a two-way road. Directed edge = a one-way road. Weighted edge = a road with a length.
  • Store it as List<List<Integer>>: graph.get(u) = neighbours of u.
  • Always keep a visited set or array. Without it, cycles make you loop forever.
  • BFS (queue) explores in rings, nearest first. It finds the shortest path when all edges have the same cost.
  • DFS (recursion or stack) goes as deep as possible, then backs up.

static List<Integer> bfs(List<List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();          // visit order
    boolean[] visited = new boolean[graph.size()];
    Queue<Integer> queue = new ArrayDeque<>();

    queue.offer(start);
    visited[start] = true;                              // mark when you add it
    while (!queue.isEmpty()) {
        int node = queue.poll();                        // take the oldest
        order.add(node);
        for (int next : graph.get(node)) {              // look at neighbours
            if (!visited[next]) {
                visited[next] = true;
                queue.offer(next);                      // visit it later
            }
        }
    }
    return order;
}

static void dfs(List<List<Integer>> graph, int node, boolean[] visited) {
    visited[node] = true;                               // mark this node
    for (int next : graph.get(node)) {
        if (!visited[next]) {
            dfs(graph, next, visited);                  // go deeper
        }
    }
}

Time & space: O(V + E) time — each node (V) and each edge (E) is looked at once. O(V) space for visited and the queue.

Remember: graph = adjacency list + visited. BFS for "shortest steps", DFS for "can I reach / explore everything".

17. Union-Find

In plain words

Union-Find (also called Disjoint Set) keeps track of groups. It answers two questions fast: "Are A and B in the same group?" (find) and "Join the groups of A and B" (union). Advanced — come back later if graphs still feel new.

Friend circles at school. Each circle has a leader. To check if two students are in the same circle, ask each one "who is your leader?". If the leaders are the same, they are in the same circle.

Key points

  • Each item has a parent. The item that is its own parent is the group's leader (root).
  • find(x) follows parents up to the leader.
  • union(a, b) makes one leader the parent of the other leader.
  • Path compression: while finding, point everyone straight to the leader. This makes it almost O(1).
  • Use it for: counting connected groups, and finding a cycle in an undirected graph.

class UnionFind {
    int[] parent;

    UnionFind(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;   // everyone leads their own group
    }

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);   // path compression: jump to the leader
        }
        return parent[x];
    }

    boolean union(int a, int b) {
        int rootA = find(a), rootB = find(b);
        if (rootA == rootB) return false;  // already in the same group
        parent[rootA] = rootB;             // join the two groups
        return true;
    }
}

Time & space: almost O(1) per find/union with path compression. O(n) space for the parent array.

Remember: "groups", "connected", "same set" → Union-Find. If union returns false, that edge makes a cycle.

18. Segment & Fenwick Trees

In plain words

Advanced — come back later. These trees answer "what is the sum (or min, or max) of items from index L to R?" fast, even when the items keep changing. If the array never changes, a simple prefix sum (topic 32) is enough.

A school with class totals and a school total. If one student's mark changes, you update their class total and the school total. You don't add up every student again.

Key points

  • Array never changes → use prefix sums: O(1) per query.
  • Array changes often → use a Fenwick tree (Binary Indexed Tree) or a segment tree.
  • Both do update and range-query in O(log n).
  • Fenwick tree: shorter code, good for sums. Segment tree: more code, but works for min, max and more.
  • These are rare in beginner interviews. Learn them after you are comfortable with everything else.

class Fenwick {
    int[] tree;
    Fenwick(int n) { tree = new int[n + 1]; }

    void add(int i, int delta) {            // add delta at position i (1-based)
        for (; i < tree.length; i += i & (-i)) {
            tree[i] += delta;
        }
    }

    int prefixSum(int i) {                  // sum of positions 1..i
        int sum = 0;
        for (; i > 0; i -= i & (-i)) {
            sum += tree[i];
        }
        return sum;
    }

    int rangeSum(int left, int right) {     // sum of positions left..right
        return prefixSum(right) - prefixSum(left - 1);
    }
}

19. Sorting

In plain words

Sorting means putting items in order, like smallest to largest. Many problems become easy after sorting. In real code you just call Arrays.sort(). But you should know how a simple sort works inside.

Sorting playing cards in your hand. You pick up one card at a time and slide it left until it is in the right place. That is insertion sort.

Key points

  • Simple sorts (bubble, selection, insertion) are O(n²). Fine for small arrays, slow for big ones.
  • Fast sorts (merge sort, quick sort) are O(n log n).
  • Arrays.sort(int[]) is O(n log n). Use it in interviews unless they ask you to write a sort.
  • A stable sort keeps equal items in their original order. Merge sort is stable.
  • Sort objects with a comparator: Arrays.sort(people, (a, b) -> a.age - b.age).

20. Binary Search

In plain words

Binary search finds an item in a sorted array by looking at the middle. If the middle is too small, throw away the left half. If too big, throw away the right half. Repeat.

Finding a word in a paper dictionary. You open it in the middle. "M"? Your word starts with "D", so you only look in the first half. You never read every page.

Key points

  • The array must be sorted.
  • Keep two indexes: lo (left end) and hi (right end). Loop while lo <= hi.
  • Middle: mid = lo + (hi - lo) / 2. This avoids number overflow for huge indexes.
  • Too small → lo = mid + 1. Too big → hi = mid - 1.
  • Off-by-one mistakes are common. Test with 1 item and 2 items.

static int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {                     // still something to check
        int mid = lo + (hi - lo) / 2;      // the middle index
        if (arr[mid] == target) {
            return mid;                    // found it
        } else if (arr[mid] < target) {
            lo = mid + 1;                  // too small: search the right half
        } else {
            hi = mid - 1;                  // too big: search the left half
        }
    }
    return -1;                             // not found
}

Time & space: O(log n) time — the search area halves every step. O(1) space.

Remember: sorted input + "find" → binary search. Use lo <= hi and move to mid + 1 / mid - 1.

21. Backtracking

In plain words

Backtracking tries every choice, one step at a time. If a path is done (or wrong), it goes back one step and tries the next choice. The pattern is always: choose → explore → un-choose.

Walking through a maze. At each fork you pick a path. If you hit a dead end, you walk back to the last fork and try another path.

Key points

  • It is recursion that builds an answer bit by bit in a list (often called path).
  • Choose: add an item to path. Explore: recurse. Un-choose: remove the item.
  • When saving an answer, save a copy: new ArrayList<>(path). Otherwise it changes later.
  • It is slow (often O(2ⁿ) or O(n!)), because it tries everything. That is OK — the questions expect it.
  • Used for: subsets, permutations, combinations, Sudoku, N-Queens, word search.

static void backtrack(int[] nums, int start, List<Integer> path,
                      List<List<Integer>> result) {
    result.add(new ArrayList<>(path));          // save a COPY of the current path
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                       // choose
        backtrack(nums, i + 1, path, result);    // explore
        path.remove(path.size() - 1);            // un-choose (go back)
    }
}

Remember: choose → explore → un-choose. Save copies, not the same list.

22. Greedy

In plain words

A greedy algorithm makes the best-looking choice right now and never changes its mind. Sometimes this gives the best total answer. Sometimes it does not — so you must check.

Giving change with the fewest coins: take the biggest coin that fits, again and again. With normal coins (25, 10, 5, 1) this works. With strange coins it can fail.

Key points

  • Greedy is usually sort + one loop. Fast and short.
  • It works only when a local best choice never hurts the final answer.
  • Test it with small examples. If you find a case where greedy fails, use DP (topic 24) instead.
  • Common greedy ideas: pick the earliest finish time, the smallest that fits, the biggest jump.

23. Divide & Conquer

In plain words

Divide and conquer has three steps. Divide the problem into smaller parts. Conquer (solve) each part, usually with recursion. Combine the answers. Merge sort is the classic example.

Sorting a big pile of exam papers with a friend. You each sort half. Then you merge your two sorted piles by always taking the smaller top paper.

Key points

  • Merge sort: split the array in half, sort each half, then merge the two sorted halves.
  • Merging two sorted lists is easy: compare the fronts, take the smaller one.
  • Splitting in half gives log n levels. Each level does n work. Total: O(n log n).
  • Binary search and quick sort are also divide and conquer.

static void mergeSort(int[] arr, int lo, int hi) {   // sorts arr[lo..hi]
    if (lo >= hi) return;                  // 0 or 1 item: already sorted
    int mid = lo + (hi - lo) / 2;
    mergeSort(arr, lo, mid);               // sort the left half
    mergeSort(arr, mid + 1, hi);           // sort the right half
    merge(arr, lo, mid, hi);               // combine them
}

static void merge(int[] arr, int lo, int mid, int hi) {
    int[] temp = new int[hi - lo + 1];
    int i = lo, j = mid + 1, k = 0;
    while (i <= mid && j <= hi) {          // both halves have items
        if (arr[i] <= arr[j]) temp[k++] = arr[i++];   // take the smaller
        else temp[k++] = arr[j++];
    }
    while (i <= mid) temp[k++] = arr[i++]; // copy what is left
    while (j <= hi) temp[k++] = arr[j++];
    for (k = 0; k < temp.length; k++) {
        arr[lo + k] = temp[k];             // put the merged items back
    }
}
// Call it like this: mergeSort(arr, 0, arr.length - 1);

Time & space: O(n log n) time — log n levels, n work each. O(n) extra space for the temp arrays.

Remember: divide, solve the halves, combine. Merge sort is the one to know by heart.

24. Dynamic Programming

In plain words

Dynamic Programming (DP) means: solve small problems first, save their answers, and build bigger answers from them. You never solve the same small problem twice.

Someone asks "what is 1+1+1+1+1?" You count: 5. Then they add "+1". You don't count again from the start. You remember 5 and say 6. That memory is DP.

Key points

  • DP works when the big problem is made of smaller, repeating problems.
  • State: what does dp[i] mean? Write it in words first. Example: "ways to reach step i".
  • Recurrence (the rule): how dp[i] uses smaller answers. Example: dp[i] = dp[i-1] + dp[i-2].
  • Base case: the smallest answers you know without work.
  • Top-down = recursion + a memo (saved answers). Bottom-up = fill a table with a loop.

static int climbStairs(int n) {

static int fib(int n, int[] memo) {      // call with memo = new int[n + 1]
    if (n <= 1) return n;                // base cases
    if (memo[n] != 0) return memo[n];    // already solved? reuse it
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
    return memo[n];
}

static int uniquePaths(int rows, int cols) {
    int[][] dp = new int[rows][cols];        // dp[r][c] = ways to reach (r, c)
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {

                dp[r][c] = 1;                // first row/column: only one way
            } else {
                dp[r][c] = dp[r - 1][c] + dp[r][c - 1];   // from top + from left
            }
        }
    }
    return dp[rows - 1][cols - 1];

static int rob(int[] houses) {               // House Robber: no two neighbours
    int skip = 0, take = 0;                  // best so far without / with last house
    for (int money : houses) {
        int newTake = skip + money;          // rob this one: last one must be skipped
        skip = Math.max(skip, take);         // skip this one: keep the best so far
        take = newTake;
    }
    return Math.max(skip, take);
}

26. Shortest Paths

In plain words

A shortest path is the cheapest way from one node to another. If every edge costs the same, plain BFS works. If edges have different costs (weights), use Dijkstra's algorithm. It always grows from the closest node not yet finished.

Google Maps. It does not count the number of roads. It adds up the minutes on each road and picks the fastest total route.

Key points

  • All edges equal → BFS, O(V + E).
  • Different weights, none negative → Dijkstra with a PriorityQueue, O(E log V).
  • Negative weights → Bellman-Ford (advanced — come back later).
  • Keep a dist array. Start with "infinity" everywhere, and 0 for the start.
  • When you find a shorter way to a node, update dist and put it in the heap.

static int[] dijkstra(List<List<int[]>> graph, int start) {
    int n = graph.size();
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);             // "infinity" at first
    dist[start] = 0;

    // heap of {node, distance}, smallest distance first
    PriorityQueue<int[]> heap = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));
    heap.offer(new int[] { start, 0 });

    while (!heap.isEmpty()) {
        int[] cur = heap.poll();
        int node = cur[0], d = cur[1];
        if (d > dist[node]) continue;                 // old, out-of-date entry: skip
        for (int[] edge : graph.get(node)) {
            int next = edge[0], cost = edge[1];
            if (d + cost < dist[next]) {              // found a shorter way?
                dist[next] = d + cost;
                heap.offer(new int[] { next, dist[next] });
            }
        }
    }
    return dist;
}

Time & space: O(E log V) time — each edge may push into the heap. O(V + E) space.

Remember: same cost → BFS. Different costs → Dijkstra (always expand the closest node first).

        if (sum == target) return new int[] { left, right };
        if (sum < target) left++;                 // need bigger: move left up

31. Sliding Window

In plain words

A window is a block of neighbouring items in an array or string (a subarray or substring). Sliding window moves this block step by step. Instead of adding everything again, you add the new item on the right and remove the old item on the left.

Looking out of a train window. The view slides along. A new tree appears on one side, and an old one disappears on the other. You don't look at the whole route again.

Key points

  • Fixed window: size k is given. Add the right item, remove the left item, update the answer.
  • Variable window: grow the right side; when the window breaks a rule, shrink from the left.
  • Clues in the question: "subarray", "substring", "contiguous" (next to each other), "longest", "of size k".
  • Often uses a HashMap or HashSet to track what is inside the window.
  • Both ends only move right, so it is O(n).

// Fixed window: biggest sum of k items in a row
static int maxSumOfK(int[] arr, int k) {
    int sum = 0;
    for (int i = 0; i < k; i++) sum += arr[i];    // first window
    int best = sum;
    for (int right = k; right < arr.length; right++) {
        sum += arr[right];                         // add the new item
        sum -= arr[right - k];                     // remove the old item
        best = Math.max(best, sum);
    }
    return best;
}

// Variable window: longest substring with no repeated letter
static int lengthOfLongestSubstring(String s) {
    Set<Character> inWindow = new HashSet<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        while (inWindow.contains(c)) {             // repeat! shrink from the left
            inWindow.remove(s.charAt(left));
            left++;
        }
        inWindow.add(c);                           // grow on the right
        best = Math.max(best, right - left + 1);   // window size
    }
    return best;
}

Time & space: O(n) time — each item enters and leaves the window once. O(1) for the fixed version, O(k) for the set.

Remember: "longest / shortest / best subarray or substring" → sliding window. Add on the right, remove on the left.

32. Prefix Sum & Difference

In plain words

A prefix sum array stores running totals: prefix[i] = sum of the first i items. Then the sum of any range is just one subtraction. A difference array does the opposite trick: it makes "add 5 to every item from L to R" fast.

Your bank statement shows the balance after each day. To know how much you spent from Tuesday to Friday, you don't add each purchase. You subtract: Monday's balance minus Friday's balance.

Key points

  • Build once in O(n): prefix[i + 1] = prefix[i] + arr[i], with prefix[0] = 0.

  • The extra 0 at the start removes special cases for L = 0.
  • Prefix sum + HashMap solves "count subarrays with sum k".
  • Difference array: to add v to range [L, R], do diff[L] += v and diff[R + 1] -= v, then take running totals at the end.

33. Fast & Slow Pointers

In plain words

Two pointers move through a linked list at different speeds. The slow one moves 1 step. The fast one moves 2 steps. If there is a loop (cycle), fast will catch up with slow. If there is no loop, fast reaches the end. When fast reaches the end, slow is in the middle.

Two runners on a track. If the track is a circle, the fast runner will lap the slow one and they meet. If it is a straight road, the fast runner just finishes first.

Key points

  • Find the middle of a list in one pass.
  • Detect a cycle (loop) with O(1) extra memory — no HashSet needed.
  • Always check fast != null && fast.next != null before moving fast 2 steps.

34. Monotonic Stack & Queue

In plain words

A monotonic stack is a stack that is always kept in order (for example, always getting smaller from bottom to top). Before pushing a new item, you pop every item that breaks the order. It answers "what is the next bigger (or smaller) item?" for every position in O(n).

People standing in a line, looking right. A tall person arriving blocks the view of all shorter people before them. Those shorter people have found their "next taller person" — so they leave the line.

Key points

  • Clue: "next greater", "next smaller", "how many days until warmer".
  • Store indexes in the stack, not values. Then you can find both the value and the distance.
  • When the new item is bigger than the top, the top has found its "next greater". Pop it and record the answer.
  • Each item is pushed once and popped once, so it is O(n).
  • A monotonic queue (deque) does the same for a sliding window maximum. (Advanced — come back later.)

35. Merge Intervals

In plain words

An interval is a range with a start and an end, like [1, 3]. Two intervals overlap if one starts before the other ends. To merge them, first sort by start, then walk through and join the ones that overlap.

Your calendar has meetings 1–3 pm and 2–6 pm. They overlap, so you are busy from 1 to 6 pm. That is merging.

Key points

  • Step 1: sort by start time. This is almost always the first step.
  • Overlap check (after sorting): next.start <= current.end.
  • Merge: current.end = Math.max(current.end, next.end).
  • No overlap → save the current interval and start a new one.
  • Used for meeting rooms, calendars, booking systems.

36. Cyclic Sort

In plain words

When an array holds numbers from 1 to n (or 0 to n), each number has a "home": number x belongs at index x - 1. Cyclic sort keeps swapping each number into its home. Then a missing or duplicate number is easy to spot.

Students with seat numbers walking into a classroom. Each student goes straight to their own numbered seat. An empty seat at the end shows who is absent.

Key points

  • Clue: "numbers in the range 1 to n", "find the missing / duplicate number".
  • If nums[i] is not at its home, swap it there. Do not move i yet — check the new number too.
  • If the number is already home (or its home already has the same number), move on: i++.
  • After sorting, any index i where nums[i] != i + 1 shows a problem number.
  • O(n) time and O(1) extra space — better than sorting or a HashSet.

    int i = 0;
    while (i < nums.length) {

        }

38. Tree BFS & DFS

In plain words

BFS is like reading a company chart floor by floor: the CEO, then all managers, then all staff. DFS is like following one chain of command all the way down before trying the next.

Key points

  • BFS: put the root in a queue. Each round, take out all nodes of the current level and add their children.
  • Use BFS for: level order, "minimum depth", "rightmost node of each level".
  • DFS: preorder (node, left, right), inorder (left, node, right), postorder (left, right, node).
  • Use DFS for: height, path sums, checking a property of every subtree.
  • Trick for BFS levels: save size = queue.size() at the start of each level, then loop exactly that many times.

static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) return result;
    Queue<TreeNode> queue = new ArrayDeque<>();
    queue.offer(root);
    while (!queue.isEmpty()) {
        int size = queue.size();                 // nodes in this level
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode node = queue.poll();
            level.add(node.val);
            if (node.left != null) queue.offer(node.left);    // next level
            if (node.right != null) queue.offer(node.right);
        }
        result.add(level);
    }
    return result;
}

// DFS: is there a root-to-leaf path that adds up to target?
static boolean hasPathSum(TreeNode root, int target) {
    if (root == null) return false;
    if (root.left == null && root.right == null) {   // leaf
        return root.val == target;
    }
    int rest = target - root.val;                     // what is still needed
    return hasPathSum(root.left, rest) || hasPathSum(root.right, rest);
}

Time & space: O(n) time for both — each node once. BFS uses O(width) space, DFS uses O(height) space.

39. Top K & K-way Merge

In plain words

Top K means "find the k biggest / smallest / most frequent items". Use a heap of size k. K-way merge means "merge k sorted lists into one sorted list". Put the first item of each list in a min-heap, and keep taking the smallest.

Top K: a talent show keeps only the best 3 acts on stage. When a better act arrives, the weakest one on stage leaves. K-way merge: k queues at a bank, and the next served is always the person with the earliest ticket among all queue fronts.

Key points

  • k largest → min-heap of size k (the smallest of the best k sits on top, easy to kick out).
  • k most frequent → count with a HashMap first, then use the heap on the counts.
  • K-way merge → heap holds one item from each list. Poll the smallest, then push the next item from that same list.
  • Time is O(n log k), which beats sorting everything (O(n log n)) when k is small.

static int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int x : nums) count.put(x, count.getOrDefault(x, 0) + 1);   // 1. count

    // 2. min-heap ordered by count: the least frequent is on top
    PriorityQueue<Integer> heap =
        new PriorityQueue<>(Comparator.comparingInt(n -> count.get(n)));
    for (int num : count.keySet()) {
        heap.offer(num);
        if (heap.size() > k) heap.poll();        // drop the least frequent
    }

    int[] result = new int[k];                   // 3. the heap holds the answer
    for (int i = 0; i < k; i++) result[i] = heap.poll();
    return result;
}

class MedianFinder {
    PriorityQueue<Integer> low = new PriorityQueue<>(Collections.reverseOrder()); // max-heap
    PriorityQueue<Integer> high = new PriorityQueue<>();                         // min-heap

    void addNum(int num) {
        low.offer(num);                       // 1. add to the small half
        high.offer(low.poll());               // 2. move the biggest small one up
        if (high.size() > low.size()) {       // 3. keep low the same size or bigger
            low.offer(high.poll());
        }
    }

    double findMedian() {
        if (low.size() > high.size()) return low.peek();     // odd count
        return (low.peek() + high.peek()) / 2.0;              // even count
    }
}

Time & space: O(log n) per add, O(1) for the median. O(n) space.

Remember: median of changing data → max-heap for the small half, min-heap for the big half.

41. Subsets & Permutations

In plain words

These are backtracking problems (topic 21). A subset is any group of the items (order does not matter). A permutation is an ordering of all the items (order matters). A combination is a group of exactly k items.

Pizza toppings. Subsets: every possible set of toppings you could choose. Permutations: every order you could put 3 toppings on the pizza, one after another.

static List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    build(nums, new boolean[nums.length], new ArrayList<>(), result);
    return result;
}

static void build(int[] nums, boolean[] used, List<Integer> path,
                  List<List<Integer>> result) {
    if (path.size() == nums.length) {            // all items placed
        result.add(new ArrayList<>(path));       // save a copy
        return;
    }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;                   // already in the path
        used[i] = true;                          // choose
        path.add(nums[i]);
        build(nums, used, path, result);         // explore
        path.remove(path.size() - 1);            // un-choose
        used[i] = false;
    }
}

Time & space: O(n! × n) time — n! orderings, each copied. O(n) space for the recursion.

Remember: subsets → loop from start. Permutations → loop from 0 with used[].

42. Modified Binary Search

In plain words

Binary search (topic 20) can do more than "find x". You can change it to find the first or last position of x, search in a rotated sorted array, or even search for the answer itself ("what is the smallest speed that works?").

Looking for the first page of chapter 5 in a book. When you land on a chapter 5 page, you don't stop — you keep looking to the left to see if chapter 5 starts earlier.

Key points

  • First position: when you find x, save it, then keep searching left (hi = mid - 1).
  • Last position: same, but keep searching right.
  • Rotated array (like [4, 5, 6, 1, 2, 3]): one half is always sorted. Check if x is in that half.
  • Search on the answer: if "does value v work?" is no, no, no, yes, yes, yes, binary search for the first yes.
  • The question's clue is often "sorted" plus "O(log n)".

static int firstPosition(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    int answer = -1;                      // -1 if never found
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] == target) {
            answer = mid;                 // found one, save it
            hi = mid - 1;                 // but maybe there is an earlier one
        } else if (arr[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return answer;
}

Time & space: O(log n) time, O(1) space — still halving every step.

Remember: found it? Save the answer and keep searching in the direction you need.

43. Topological Sort

In plain words

Topological sort puts tasks in an order where every task comes after the tasks it depends on. It works on a directed graph with no cycles. The in-degree of a node is how many arrows point into it — how many tasks must happen before it.

Getting dressed. Socks before shoes. Shirt before jacket. You can start with anything that has nothing before it, and the order follows from there.

Key points

  • Kahn's algorithm: start with all nodes that have in-degree 0 (nothing before them). Put them in a queue.
  • Take one out, add it to the order, and lower the in-degree of its neighbours by 1.
  • When a neighbour reaches in-degree 0, it is ready — add it to the queue.
  • If the final order has fewer than n nodes, there is a cycle (impossible to finish).
  • Clue: "prerequisites", "dependencies", "build order", "can all courses be finished?"

// prereqs[i] = {course, before}: "before" must be taken before "course"
static List<Integer> courseOrder(int n, int[][] prereqs) {
    List<List<Integer>> graph = new ArrayList<>();
    for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
    int[] inDegree = new int[n];
    for (int[] p : prereqs) {
        graph.get(p[1]).add(p[0]);        // arrow: before -> course
        inDegree[p[0]]++;                 // course has one more thing before it
    }

    Queue<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) queue.offer(i);   // ready to start
    }

    List<Integer> order = new ArrayList<>();
    while (!queue.isEmpty()) {
        int course = queue.poll();
        order.add(course);
        for (int next : graph.get(course)) {
            inDegree[next]--;             // one less thing to wait for
            if (inDegree[next] == 0) queue.offer(next);
        }
    }
    return order.size() == n ? order : new ArrayList<>();   // empty = cycle
}

Time & space: O(V + E) time — each course and each arrow once. O(V + E) space for the graph.

Remember: start from in-degree 0, remove it, lower the neighbours. Fewer than n in the order → cycle.
Practice: Course Schedule (#207), Course Schedule II (#210).

44. Matrix & Islands

In plain words

A matrix (grid) is a 2D array: rows and columns. Many grid problems are graph problems in disguise. Each cell is a node, and its 4 neighbours (up, down, left, right) are its edges. An island is a group of connected land cells.

A paint bucket tool in a drawing app. You click one pixel, and the colour spreads to every touching pixel of the same colour. That spreading is DFS on a grid.

Key points

  • A cell is grid[r][c]: r = row, c = column.
  • Always check the borders first: r >= 0 && r < rows && c >= 0 && c < cols.
  • Mark visited cells, often by changing '1' to '0' (sinking the land).
  • Number of islands = how many times you start a new DFS on unvisited land.
  • Use BFS instead when the question asks for the shortest number of steps.

static int numIslands(char[][] grid) {
    int count = 0;
    for (int r = 0; r < grid.length; r++) {
        for (int c = 0; c < grid[0].length; c++) {
            if (grid[r][c] == '1') {       // new land we have not visited
                count++;                   // found a new island
                sink(grid, r, c);          // mark the whole island as visited
            }
        }
    }
    return count;
}

static void sink(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length) return;  // outside
    if (grid[r][c] != '1') return;         // water or already visited
    grid[r][c] = '0';                      // mark as visited
    sink(grid, r + 1, c);                  // down
    sink(grid, r - 1, c);                  // up
    sink(grid, r, c + 1);                  // right
    sink(grid, r, c - 1);                  // left
}

Time & space: O(rows × cols) time — each cell is visited once. O(rows × cols) space for the recursion in the worst case.

Remember: grid = graph. Check borders, mark visited, explore 4 directions.
Practice: Flood Fill (#733), Number of Islands (#200), Max Area of Island (#695).

45. Design Problems

In plain words

In a design problem, you build a small class with a few methods, and each method must be fast. The trick is to combine data structures. Example: an LRU cache (Least Recently Used) keeps the most recently used items and throws out the oldest one when it is full.

A small desk that fits only 2 books. When you need a third book, you put away the book you haven't touched for the longest time.

Key points

  • First, list each method and the speed it needs (often O(1)).
  • Then pick structures: HashMap for fast lookup, a linked list or deque for order, a heap for min/max.
  • Min Stack: a normal stack plus a second stack that tracks the minimum so far.
  • LRU Cache: HashMap + doubly linked list. In Java, LinkedHashMap already combines them.
  • Interviewers may ask you to build the linked list yourself — see the full notes for that version.

// LRU Cache using LinkedHashMap (keeps items in "last used" order)
class LRUCache extends LinkedHashMap<Integer, Integer> {
    int capacity;

    LRUCache(int capacity) {
        super(16, 0.75f, true);          // true = order by last access, not insert
        this.capacity = capacity;
    }

    int get(int key) {
        return getOrDefault(key, -1);    // reading also marks it "recently used"
    }

    void put(int key, int value) {
        super.put(key, value);
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
        return size() > capacity;        // too big? Java removes the oldest
    }
}

// Min Stack: getMin() in O(1)
class MinStack {
    Deque<Integer> stack = new ArrayDeque<>();
    Deque<Integer> mins = new ArrayDeque<>();     // min so far, at each level

    void push(int x) {
        stack.push(x);
        mins.push(mins.isEmpty() ? x : Math.min(x, mins.peek()));
    }
    void pop()    { stack.pop(); mins.pop(); }
    int top()     { return stack.peek(); }
    int getMin()  { return mins.peek(); }
}

Time & space: every method is O(1). O(n) space for the stored items.

Remember: design = pick the right mix of structures so every method is fast. HashMap + ordered list is the most common mix.
